AP 业务流程设计

在继续写代码前，把「什么时候扫描 / 什么时候审核 / 什么时候进 QuickBooks / 科目与税码怎么定」四件事固定下来。先看竞品实际怎么跑，再定我们的做法。

调研：Dext · Hubdoc · AutoEntry · Ramp · ApprovalMax 法规依据：CRA ITC Information Regulations 四项裁定已拍板

第一部分

竞品实际怎么跑

1.1 收单：文档驱动 vs 支出驱动

产品入口触发节奏
Dext手机拍照、专属邮箱转发、供应商门户自动抓取、拖拽上传客户随时交，随到随抽取
Hubdoc强在自动从供应商网站抓账单（水电、电信、银行对账单）系统主动抓，客户零动作
AutoEntry收据、发票、银行对账单都能抽，按额度计费批量为主
Ramp卡消费即产生记录，收据反过来后补支出发生即触发

行业实务口径一致：银行流水应每日或每周处理，不要攒到月末——「每天 5 分钟，攒到月末就是 3 小时且必出错」。

关键分野

Dext / Hubdoc 是文档驱动（等票来），Ramp 是支出驱动（先有花费，再追票）。支出驱动的完成率高得多，因为缺口是可枚举的。

1.2 审核：自动化到哪一步

  • Dext 的规则优先级：供应商规则 > 自动分类（机器学习）> 账户级默认值。ML 只在供应商规则没填时才填。
  • Auto-publish：可在供应商级 / 支付方式级 / 全账户级打开，抽取完即推送到会计软件。但业界指导明确警告：只对「规则齐备、科目固定」的供应商开；支付方式级基本不建议开；有审批流时一律不自动发布。
  • AI Assist：用自然语言写指引处理规则覆盖不了的歧义。例：「Tesco 小票里出现 fuel / petrol / diesel 记差旅-国内、零税率，否则记一般费用」。
  • ApprovalMax + Dext：Dext 只做抽取，审批流走完才推 QBO，并把审批历史 PDF 一起挂到 Bill 上。
市场信号

新入场者拿「字段级置信度 + 强制人工复核门禁（未批不得过账）+ 每客户规则隔离 + 完整审计轨迹」当卖点 —— 说明 Dext 式自动发布在会计师眼里是有风险敞口的。

1.3 进 QuickBooks 的时机与形态

  • Dext：点 Publish 才进 QBO。发布前必须配好税率默认值，否则 QBO 拒收（QBO 要求每一行都有有效税码）。
  • Ramp：同步为 Expense；同步后在 Ramp 侧锁定，之后任何修改必须去 QBO 改。
  • ApprovalMax：审批完成才推，原件 + 审计报告一并作为附件挂到 Bill。
这里有个我们代码目前踩了的坑

已付的收据应记成 Expense / Purchase（直接冲银行或信用卡），只有未付的发票才记 Bill 挂应付账款。选错会导致应付账款虚增、银行对不上。现有代码只会建 Bill。

1.4 加拿大税：通用工具管不了的地方

所有竞品都不靠 AI 猜税码，走「默认税率 + 供应商规则 + 税码表」。而加拿大特有的三个坑，通用工具基本不处理：

  • 餐饮招待 50% 限制：QBO Canada 的标准做法是建 group rate——一半走可抵扣 ITC，一半走计入费用。不是简单选一个 HST 税码。
  • PST / QST 不可抵扣：只有 GST/HST 部分能抵 ITC，PST 要计入费用成本。
  • CRA 抵扣凭证三档硬要求：直接决定这张票能不能抵税。
票面总额必须具备的信息
< $30供应商名 / 商号、日期、总额
$30 – $150上述 + 供应商 GST/HST 登记号 + 税额或含税声明
≥ $150上述 + 购方名称、付款条款、每项供应的描述
这就是差异化的入口

一张 $200 的票如果没有供应商 GST/HST 号，这笔 ITC 抵不了。通用 OCR 工具不管这件事，而会计师每天在踩。

第二部分

易账的流程定稿
一句话定位

不是「等客户交票」，而是用银行流水倒逼把票补齐，再把每张票按加拿大税规则记对账。收单靠客户，完整性靠对账，正确性靠规则 + AI，风险靠 CRA 凭证校验。

2.1 主流程

1

收单随时

邮箱转发 / 上传 / 后续手机拍照。文件指纹去重，落 received。

2

识别收单即触发

OCR + 行项目抽取。除金额外，必抽 CRA 要件：供应商名、日期、总额、税额、GST 号、购方名。

3

定科目、定税码紧随识别

科目：供应商规则 → 关键词规则 → AI 逐行 → 人工。税码：确定性规则表，AI 不参与。产出行级科目 + 税码 + 置信度 + 凭证等级。

4

复核每周，不攒月末

队列排序：凭证风险 > 置信度 > 金额。符合绿色通道条件的可跳过人工。

5

录入 QBO确认即录入

已付 → Expense，未付 → Bill；原件作附件挂上；synced 后本地转只读，QBO 成为权威。

A

护栏 A · 银行对账（每周）

逐笔比对银行流水与已收单据，缺收据清单直接变成追票工单。这是收单的主引擎，不是附属功能。

B

护栏 B · CRA 凭证校验（持续）

按金额档校验凭证要件，月末出「不可抵扣清单」。是风险信号不是拦截器——凭证不全照样入账，只是这笔 ITC 不能抵。

2.2 四个时机的裁定

问题裁定理由
什么时候扫描收单即扫，不排队不批处理客户交票时间不可控；识别越早，缺什么越早知道。同步处理也保住 Cloud Run 缩容到零
什么时候审核按周复核，按「凭证风险 > 置信度 > 金额」排序攒到月末必出错是行业共识；凭证缺陷比科目记错贵
什么时候进 QBO人工确认即录入，不等月末批量早录入才能让 QBO 的银行对账实时可用；批量出错难定位
科目怎么定规则 → AI 逐行 → 人工，AI 只建议不裁定与 Dext 优先级一致；AI 的价值在多列异形票据还原与上下文判断
税码怎么定确定性规则表，AI 只负责抽取科目记错可改，税码记错是税务风险，且规则本身确定

2.3 绿色通道：六条与门

竞品的自动发布是「供应商级开关」，太粗。我们用多条件与门，全部满足才自动过账：

  1. 命中该客户的供应商规则，且该规则已被人工确认过 ≥ 3 次
  2. 所有行的科目置信度 = 高
  3. CRA 凭证等级达标（按金额档该有的字段齐全）
  4. 金额 ≤ 客户设定阈值（默认 CAD 200）
  5. 非疑似重复单据
  6. 所有行税码由规则表命中，非 AI 推断

任一不满足即进人工复核。自动过账不新增状态，但审计留痕为 auto_confirm、操作者记为 system，并进「已自动过账」抽查列表。会计师可随时对某客户关闭绿色通道。

2.4 已付 / 未付的分叉

单据形态QBO 对象判定依据
收据（已付：刷卡 / 现金）Purchase / Expense 直接冲银行或信用卡OCR 有付款方式、票据类型为 receipt、或已匹配到银行流水
供应商发票（未付，有账期）Bill 挂应付账款，付款后记 Bill Payment有到期日 / 付款条款，且未匹配到银行流水
信用卡退款 / 贷记单Credit Note / Refund金额为负
