# 界面按业务流程重排

> 日期：2026-08-02
> 目标：让界面本身讲清流程——演示时不用旁白，日常也能一眼看出「哪一步堵了」。
> 依据：[业务流程设计](20260802-业务流程设计.md) 的五段 + 两护栏。

---

## 一、研究与取舍（reference lock）

Refero MCP 未配置，按 skill 规定改用产品证据 + bundled craft 参考，保持同样的 reference-lock 流程。

**产品模式证据**

| 来源 | 学到什么 |
|---|---|
| Light（AP 软件） | 把 15 个内部 bill 状态映射成 5 个对外 tab。→ **对外阶段要少，内部状态映射进去**。我们把 12 个 `DocStatus` 映射成 5 段 + 1 条异常旁支 |
| Dext | 抽取→规则/ML 编码→复核→publish，机器段与人工段分明。→ 界面要标出**哪几步是你的活** |
| Ramp | 同步后锁定，改要去 QBO。→ 终点段显示「已锁定」语义 |
| Preline CRM pipeline heading | 阶段头 = 阶段名 + 计数 + 状态点 |
| Linear 筛选流 | 点条件即筛列表。→ 点管道任一段即筛选该段单据 |

**craft 约束**（anti-ai-slop）

- 不用 indigo/violet（产品本就是墨绿，天然避开）
- **管道不做成五张卡片**——「处处卡片」是 AI 味第 2 号特征。改用**一条连续分段轨道**，靠量条宽度表达积压
- 卡片只用于真正的交互容器（两条护栏是可点击入口，用卡片合理）
- 不用 emoji 当图标

**Reference lock**

```
主方向：产品既有 token（墨绿 ink / 暖金 gold / 置信度三色），数据密集型财务工具
保留：白底、紧凑排版、细边框、tabular-nums
形态：连续分段轨道，不是卡片阵列；量条表达积压，不靠读数字
拒绝：indigo、卡片堆砌、暗色默认、calm editorial serif、emoji 图标
```

**段色（2026-08-02 修订）**：初版把五段全压在墨绿系深浅里，为的是不动状态语义色——
实际用下来区隔太弱，两轮反馈都说分不开。改判：**段色是地铁线路色，标「第几段」不标好坏**，
因此可以放开色相，只需守住两条红线——警示红留给 `conf-low`，完成绿留给「已录入」。

| 段 | 色带（亮版） | 序号圆（深版） | 白字对比度 |
|---|---|---|---|
| ① 收单 | `#1e5f8e` 钢蓝 | `#17496e` | 9.48 |
| ② 识别 | `#0d8a80` 青绿 | `#0b7269` | 5.79 |
| ③ 定科目税码 | `#2f7d63` 绿 | `#1f4d3f` | 9.58 |
| ④ 复核 | `#c88a2e` 暖金 | `#8a5d19` | 5.74 |
| ⑤ 录入 QBO | `#a8481f` 赤陶 | `#8a3b18` | 7.72 |

冷→暖的色相路径（蓝→青→绿→金→赤陶）让推进感由颜色本身承担。色带 6px（选中 9px）。
对比度为浏览器实测值，全部过 WCAG AA。这组色定义为 `--color-stage-{1..5}` 与 `-deep`，
**只允许用于流程段标识**，不得用于状态表达。

⚠️ 已知取舍：⑤ 的赤陶 `#a8481f` 与警示红 `#c0453b` 色相相邻。二者在界面上位置分离
（段色只出现在管道色带与序号圆，警示红只出现在徽章与文字），加上序号数字辅助识别。
若实际使用中仍会混淆，⑤ 可换成深青蓝 `#0e5c6b`。

## 二、决策台账

| 决策 | 来源 | 为什么 |
|---|---|---|
| 五段 + 异常旁支，而非暴露 12 个状态 | Light 的 5 tab 映射 | 会计师不需要理解 `ocr_done` 与 `classifying` 的区别 |
| 管道段标「需人工」 | Dext 机器段/人工段之分 | 用户第一眼要找的是「哪几步要我干活」 |
| 堵点只标人工段 | 自定 craft 规则 | 机器段的积压会自己流走，标红是噪音 |
| 点击段即筛选列表 | Linear 筛选流 | 管道不只是仪表盘，是导航器 |
| 轨道而非卡片阵列 | anti-ai-slop #2 | 五张带阴影的卡片是 AI 默认布局 |
| 堵点用暖金不用红 | 色彩角色锁 | 红已经承担「凭证风险/异常」，不能一色两义 |
| 队列页并入工作台 | 全链重排目标 | 两个入口讲同一件事会稀释流程感 |
| 复核页顶部步骤条 | 同上 | 进到子页面流程感不能断 |
| 侧边栏复核时也高亮当前客户 | 导航连贯性 | 复核页 URL 没有 clientId，由服务端反查补上 |

## 五、演示动线

1. **客户列表** → 三个数就是流程口径（处理中 / 待复核 / 已录入）
2. **进客户** → 五段轨道，一眼看到「④ 复核 3 张 ← 堵在这」，两条护栏写着缺收据 6 笔、凭证缺件 3 张
3. **点第 ④ 段** → 列表立刻只剩待复核的，标题变「第 4 步 · 复核」
4. **点复核** → 顶部步骤条显示你在第 4 步，前三步已变绿；左栏真实原件，中栏科目+税码，右栏 Bill/Purchase 预览
5. **确认 → 录入 QBO** → 回到工作台，单据从 ④ 流到 ⑤，再流到「已录入」
6. **点护栏「去对账追票」** → 缺收据清单 → 一键生成催票内容
7. **上传一张新单** → 进度按「① 收单 → ② 识别 → ③ 定科目税码」走，落到 ④ 等复核；若命中绿色通道六条，直接跳到「已录入」
