# 功能缺口盘点（按流程五段 + 两护栏）

> 日期：2026-08-02
> 方法：对着代码逐项核对，不凭印象。已核查全部 12 个 API 路由、7 个页面、组件层。
> 标记：🔴 阻断真实使用 · 🟡 影响可用性 · ⚪ 增强

---

## ① 收单

**已有**：手动上传（单文件）、20MB/类型白名单校验、文件指纹去重、状态落 `received`。

| 缺口 | 级别 | 说明 |
|---|---|---|
| **银行流水导入** | 🔴 | 对账追票是收单的主引擎（已定的第 3 条裁定），但流水目前**只能靠 seed 造**。缺 CSV/OFX 上传或银行 feed，真实客户用不起来 |
| **邮件入站 webhook** | 🔴 | `proxy.ts` 已放行 `/api/inbound/email`，**路由不存在**。客户「转发发票到专属邮箱」这条主入口是空的，设置页还在对外展示这个邮箱 |
| **客户 CRUD** | 🔴 | 客户列表的「+ 新增客户」是**死按钮**，只能靠 seed 建客户 |
| 批量上传 | 🟡 | 一次一个文件，会计师积攒一叠票时很痛苦 |
| 拖拽上传 | 🟡 | 现在必须点按钮选文件 |
| 客户自助交票 | 🟡 | 只有会计师账号，客户无法自己传 |
| 手机拍照 | ⚪ | 竞品标配（Dext/Hubdoc），需移动端或 PWA |
| 供应商门户自动抓取 | ⚪ | Hubdoc 的强项（自动抓水电、电信账单） |

## ② 识别

**已有**：OcrProvider 抽象、Veryfi 实现、mock 兜底、CRA 凭证字段抽取、失败落 `ocr_failed`、重跑接口（失败不毁旧数据）。

| 缺口 | 级别 | 说明 |
|---|---|---|
| **可用的 OCR 供应商** | 🔴 | Veryfi 试用已到期（`403 trial has ended`）。**当前没有任何可真跑的 OCR**，新上传只会落 `ocr_failed` |
| **失败重试 + 退避** | 🔴 | DEV-PLAN P2 明确要求「重试 3 次 + 退避」，代码里**一次失败就终止**。网络抖动会直接把单据打成 `ocr_failed` |
| **异步处理** | 🟡 | OCR 同步阻塞上传响应。大 PDF 或 OCR 慢时前端会卡住甚至超时 |
| **多列表格补全（ocr_text → Claude）** | 🟡 | 车行发票那类多列表格（principal/interest/fees）被压成「描述 + 一个 total」，列拆不开科目就分不对。原定的重点功能，代码未动 |
| OCR 漏行时的手工补行 | 🟡 | 见 ④ 复核 |
| HEIC 实际可用性 | ⚪ | 白名单放行了，但没验证过 OCR 端是否吃这个格式 |

## ③ 定科目税码

**已有**：规则优先（vendor/keyword）、65 商户种子表、Claude 分类器代码、确定性税码规则表、未命中留空强制人工。

| 缺口 | 级别 | 说明 |
|---|---|---|
| **税码 semanticKey 指认界面** | 🔴 | 连上 QBO 后同步来的税码**没有 semanticKey**（系统不猜，契约 G10）。没有界面去人工指认「哪个税码是标准可抵扣 / 餐饮 50% / 不可抵扣」，**规则表就映射不到实际税码，全部行税码留空** |
| **ANTHROPIC_API_KEY** | 🟡 | 未配置，逐行分类走 mock。规则命中不了的行只能人工 |
| **规则管理界面** | 🟡 | `ClassificationRule` 只能靠确认时自动学习生成，**无法查看、编辑、删除**。学错了没法改 |
| **keyword 规则的创建入口** | 🟡 | 数据结构支持，但只有 seed 里那一条，UI 无从创建 |
| 科目/税码表定期重新同步 | 🟡 | 只在 OAuth 回调时同步一次。客户在 QBO 里新增科目后，这边看不到 |
| 一行拆多科目 | ⚪ | 一行费用要分摊到两个科目时做不到 |
| AI Assist 式自然语言规则 | ⚪ | Dext 的做法：「Tesco 含 fuel 记差旅，否则记一般费用」 |

## ④ 复核

**已有**：三栏工作台、真实原件预览、行级科目+税码选择、凭证风险提示条、按风险排序、确认落库、学习飞轮、重新识别、付款状态切换。

| 缺口 | 级别 | 说明 |
|---|---|---|
| **抬头字段不可编辑** | 🔴 | 只能改科目和税码。**金额、日期、供应商、发票号、税额全部改不了** —— OCR 抽错了就只能重跑，重跑还是错就没救了。这是复核工作台最硬的缺口 |
| **加行 / 删行** | 🔴 | OCR 漏抽一行时无法补，多抽一行时无法删。行合计对不上票面总额也只能干看着 |
| **退回（rejected）** | 🟡 | 状态机里有 `rejected`，**没有接口也没有按钮**（原来那个死按钮我已移除）。垃圾单据无法出队 |
| 上一张 / 下一张 | 🟡 | 复核完必须返回列表再点下一张，批量复核时很低效 |
| 批量确认 | 🟡 | 一次只能确认一张 |
| 键盘快捷键 | 🟡 | 复核是高频重复操作，纯鼠标操作效率低 |
| 备注 / 沟通记录 | ⚪ | 「这张为什么这么记」无处留言 |

## ⑤ 录入 QBO

**已有**：OAuth 连接（state 签名校验）、refresh token 加密+轮换、按付款状态建 Bill/Purchase、原件挂 Attachable、QBO 侧去重、状态机与失败重试入口、科目/税码首次同步。

| 缺口 | 级别 | 说明 |
|---|---|---|
| **真实 Intuit 实测** | 🔴 | 无 sandbox 凭据，全链只在 mock 上验证过。`minorversion`（暂用 75）、加拿大税字段（`GlobalTaxCalculation` / 行级 `TaxCodeRef`）都未经真实验证 |
| **429 限流退避** | 🟡 | 代码只在错误信息里带上 `Retry-After`，**没有真的退避重试** |
| 批量录入 | 🟡 | 已确认的单据只能一张张点录入 |
| 跳转 QBO 查看 | 🟡 | `synced` 后只显示 id，没有直达 QBO 该单据的链接 |
| 撤销 / 作废 | 🟡 | 录错了只能去 QBO 手动删，本地状态会与 QBO 不一致 |
| Vendor 名模糊匹配 | ⚪ | 「Tim Hortons」与「TIM HORTONS #4021」会建成两个供应商 |
| 多币种 | ⚪ | `CurrencyRef` 透传了，但汇率与外币账单未处理 |

**已有**：一对一自动匹配（容差+日期窗+供应商命中）、人工裁决优先、缺收据清单、催票内容生成、`ChaseNotice` 落库、已催次数展示。

| 缺口 | 级别 | 说明 |

| **流水导入** | 🔴 | 同 ① —— 没有导入就没有对账 |

| 追票效果追踪 | ⚪ | 催了之后客户补没补，只能看流水是否被匹配 |

## 如果按「能不能给真实客户用」排序

前五件事，缺一不可：

1. **定 OCR 供应商** —— ② 段完全断了，一切下游无从谈起
2. **银行流水导入** —— 护栏 A 的前提，也是收单主引擎
3. **邮件入站 webhook** —— 客户交票的主通道，现在对外承诺了却不通
4. **复核页抬头字段可编辑 + 加删行** —— OCR 必然出错，没有人工兜底的复核台不成立
5. **税码 semanticKey 指认界面** —— 不做这个，接了真实 QBO 后所有行的税码都是空的

其后是：Intuit 实测、客户 CRUD、人工匹配界面、加拿大区部署。
