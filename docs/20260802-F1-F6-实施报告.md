## 一、做了什么

### F1 · schema 增量
4 次 migration 已应用到 Neon：`Document.settlement/qboEntity`、`Extraction` 三个 CRA 凭证字段、`ClassificationRule.confirmedCount`、`Client` 五项配置（省份/税号/付款账户/绿色通道开关/阈值）、新表 `TaxCodeCache`（含 `semanticKey`）与 `ChaseNotice`。

### F2 · CRA 抵扣凭证等级
- `src/domain/itc.ts`：按 CRA 三档要求实时派生（不物化），产出 `ok | incomplete | not_applicable | unknown` + 缺失字段列表。
- **免税单据（税额为 0）判为 not_applicable**——本就没有 ITC 可抵，不该报缺件。
- OCR 层新增抽取：供应商 GST/HST 号、购方名称、付款条款（Veryfi 映射 + mock 三种凭证形态）。
- 队列排序改为**凭证风险 > 置信度 > 金额**；队列列出「抵扣凭证」徽章，复核页顶部红条直接写明「这笔进项税抵不了，还缺 X」。

### F3 · 税码规则表
- `src/domain/tax-rules.ts`：`票面税额 → 供应商登记状态 → 科目类别` 的确定性规则，产出 4 种税务处理语义（standard / meals_50 / no_itc / no_tax）。
- **语义键经 `TaxCodeCache.semanticKey` 映射到客户实际 QBO 税码**——同一套规则适配不同省份、不同客户的税码表。
- 未命中 → 税码留空 + 该行降为低置信 + 复核页标红「税码待人工确定」，**绝不兜底猜**（契约 G10）。
- 确认时校验每行税码有效，缺税码不得录入（QBO 会拒收）。

### F4 · 录入 QBO
- `QboProvider` 接口 + mock + 真实 Intuit 实现；OAuth connect/callback（state 用签名 JWT，校验 clientId + firmId）。
- **refresh token AES-256-GCM 加密存储**，刷新时轮换并回写。
- **按 `settlement` 分叉**：未付 → Bill（挂 AP），已付 → Purchase（冲银行/信用卡，必须先配付款账户）。
- 附件挂 Attachable；QBO 侧按 vendor+DocNumber 二次去重；连接成功自动同步科目表与税码表。
- 状态机：`confirmed → syncing_qbo → synced`，失败落 `sync_failed` 可重试；`synced` 后本地只读。

### F5 · 绿色通道六条与门
- `src/domain/auto-post.ts`：六条全过才自动过账，未过时**返回具体未过哪几条**（UI 可解释）。
- 自动过账**不累加** `ClassificationRule.confirmedCount`——否则规则自我强化，条件 1 就失去意义。
- 审计留 `auto_confirm` + `userId=system`，队列打「自动过账」标记供抽查。
- 客户设置页可开关、设阈值，六条门禁明写在页面上。

### F6 · 追票工单
- 缺收据清单 → 一键生成催票内容（逐笔列出日期/摘要/金额 + 合计 + 为什么要补票），落 `ChaseNotice`。
- **只存「催过没有」，不存「解决了没有」**——是否解决由当前匹配状态派生（契约 §4.12），避免补票后两处不一致。
- 邮件通道未接：**只生成草稿、不假装已发送**，弹窗给出全文供复制，记录 channel=manual。

## 三、诚实的边界

1. **真实 Intuit API 未实测**——没有 sandbox 凭据，F4 的真实实现是按已验证的 API 文档写的，`minorversion`（暂用 75）与加拿大税字段组合（`GlobalTaxCalculation` / 行级 `TaxCodeRef`）需要拿到凭据后实测确认。mock 全链通过不等于真实链路通过。
2. **OCR 仍阻塞**——Veryfi 试用到期，本轮所有验证用 mock OCR。真实票据上能否稳定抽到 GST 号，需要换 OCR 供应商后重测。
3. **税码 seed 是安大略 demo 值**——真实客户连上 QBO 后会同步真实税码，但 `semanticKey`（规则表的桥）需要人工指认一次，系统不猜。
4. **邮件未接**——追票只出草稿。
5. **`no_itc` 税额并入成本的会计处理**依赖 QBO 侧税码本身配置正确，我方不自己算税（契约 G6）。
