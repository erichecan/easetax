## 一、竞品实际怎么跑（调研结论，非猜测）

### 1.1 收单（什么时候扫描）

| 产品 | 入口 | 触发节奏 |
|------|------|---------|
| **Dext** | 手机拍照、专属邮箱转发、供应商门户自动抓取（Fetch）、拖拽上传 | 客户随时交，系统随到随抽取 |
| **Hubdoc** | 强在**自动从供应商网站抓账单**（水电、电信、银行对账单），定期登录抓取 | 系统主动抓，客户零动作 |
| **AutoEntry** | 收据/发票/**银行对账单**都能抽，按额度计费 | 批量为主 |
| **Ramp** | 卡消费即产生记录，**收据反过来后补**（刷卡→催员工传票） | 支出发生即触发 |

**行业共识**（多份记账实务指南口径一致）：银行流水**每日或每周**处理，不要攒到月末——"每天 5 分钟，攒到月末就是 3 小时且必出错"。

**关键分野**：Dext/Hubdoc 是**文档驱动**（等票来），Ramp 是**支出驱动**（先有花费，再追票）。支出驱动的完成率更高，因为缺口是可枚举的。

### 1.2 审核（什么时候审核、审到什么程度）

- **Dext**：抽取完成 → 规则与 ML 自动编码 → 落 inbox → 会计师复核 → publish。
  - 规则优先级：**供应商规则 > 自动分类（ML）> 账户级默认值**。ML 只在供应商规则没填时才填。
  - **Auto-publish**：可在供应商级 / 支付方式级 / 全账户级打开，抽取完即推送到会计软件。
  - 但业界指导明确警告：只对"规则齐备、科目固定"的供应商开；支付方式级基本不建议开；有审批流时一律不 auto-publish。
  - **AI Assist**：用自然语言写指引处理规则覆盖不了的歧义（例："Tesco 小票里出现 fuel/petrol/diesel 记差旅-国内、零税率，否则记一般费用"）。
- **ApprovalMax + Dext**：Dext 只做抽取，**审批流走完才推 QBO**，并把审批历史 PDF 一起挂到 QBO 的 Bill 上。
- **市场反馈**：新入场者（如 ScribeosAI）拿"**字段级置信度** + **强制人工复核门禁**（未批不得过账）+ 每客户规则隔离 + 完整审计轨迹"当卖点 —— 说明 Dext 式"自动发布"在会计师眼里是有风险敞口的。

### 1.3 进 QuickBooks 的时机与形态

- **Dext**：点 Publish 才进 QBO。发布前**必须**配好税率默认值，否则 QBO 拒收（QBO 要求每一行都有有效税码）。
- **"Publish to" 的关键分叉**：**已付**的收据 → 记成 Expense / Purchase（直接冲银行或信用卡）；**未付**的发票 → 记成 **Bill**（挂 AP）。选错会导致应付账款虚增、银行对不上。
- **Ramp**：同步为 Expense；**同步后在 Ramp 侧锁定，之后任何修改必须去 QBO 改**。
- **ApprovalMax**：审批完成才推，原件 + 审计报告一并作为附件挂到 Bill。

### 1.4 科目与税码怎么定

- **科目**：供应商规则 → ML 学历史编码 → AI 上下文判断 → 人工。行项目级抽取后，每行可各自归科目。
- **税码**：全部竞品都**不靠 AI 猜**，走"默认税率 + 供应商规则 + 税码表"。QBO 的税码是每家公司自己的 `TaxCode.Id`。
- **加拿大特有的坑**（易账必须处理，通用工具处理不好的地方）：
  - **餐饮招待 50% 限制**：QBO Canada 的标准做法是建一个 **group rate**——一半走"可抵扣 ITC"，一半走"计入费用"。不是简单选一个 HST 税码。
  - **PST / QST 不可抵扣**：只有 GST/HST 部分能抵 ITC，PST 要计入费用成本。
  - **CRA 抵扣凭证三档硬要求**（ITC Information Regulations，直接决定这张票能不能抵税）：

    | 票面总额 | 必须具备的信息 |
    |---|---|
    | **< $30** | 供应商名 / 商号、日期、总额 |
    | **$30 – $150** | 上述 + **供应商 GST/HST 登记号** + 税额或含税声明 |
    | **≥ $150** | 上述 + **购方名称**、付款条款、每项供应的描述 |

  - 也就是说：**一张 $200 的票如果没有供应商 GST/HST 号，这笔 ITC 抵不了**。这是通用 OCR 工具不管、但会计师每天在踩的坑。

## 二、易账的流程定稿草案

### 2.1 一句话定位

**不是"等客户交票"，而是"用银行流水倒逼把票补齐，再把每张票按加拿大税规则记对账"。**

收单靠客户，完整性靠对账，正确性靠规则+AI，风险靠 CRA 凭证校验。

### 2.2 主流程（五段 + 两条护栏）

```
① 收单        随时（邮箱转发 / 上传 / 后续：手机拍照）
     ↓        指纹去重，落 received
② 识别        收单后立即触发（同步），OCR + 行项目
     ↓        抽 CRA 必需字段：供应商名 / 日期 / 总额 / 税额 / GST号 / 购方名
③ 定科目定税  规则 → AI → 兜底；税码走确定性规则表，不猜
     ↓        产出行级科目 + 税码 + 置信度 + CRA 凭证等级
④ 复核        每日/每周（不攒月末），低置信与凭证缺陷置顶
     ↓        绿色通道可跳过（见 2.4）
⑤ 录入 QBO    确认即录入，已付→Expense、未付→Bill；原件作附件；synced 后本地只读
─────────────
护栏 A：银行对账      每周跑，缺收据清单 = 追票工单
护栏 B：CRA 凭证校验  抵扣风险单独成列，月末出「不可抵扣清单」
```

### 2.3 时机裁定（对应你问的四个问题）

| 问题 | 裁定 | 理由 |
|------|------|------|
| **什么时候扫描** | 收单即扫，不排队、不批处理 | 客户交票时间不可控，识别越早，缺什么越早知道；同步处理也保住 Cloud Run `min-instances=0` |
| **什么时候审核** | **按周复核**（不是按月），队列按「凭证风险 > 置信度 > 金额」排序 | 攒到月末必出错，是行业共识；风险优先于置信度，因为 CRA 凭证缺陷比科目记错贵 |
| **什么时候进 QBO** | **人工确认即录入**（`confirmed → syncing_qbo → synced`），不等月末批量 | 早录入才能让 QBO 的银行对账实时可用；批量录入出错时难定位 |
| **科目怎么定** | 供应商规则 → 关键词规则 → AI 逐行 → 人工。**AI 只建议，不最终裁定** | 与 Dext 优先级一致；AI 的价值在多列/异形票据的还原和上下文判断 |
| **税码怎么定** | **确定性规则表**：省份 × 科目 × 供应商登记状态 → 税码。AI 只负责**抽取**税额/GST号/省份 | 科目记错可改，税码记错是税务风险；且加拿大税规则是确定的，没有猜的必要 |

### 2.4 绿色通道（自动过账）的门槛

竞品的 auto-publish 是"供应商级开关"，太粗。易账用**多条件与门**，全部满足才自动过：

1. 命中该客户的**供应商规则**（人工确认过至少 N 次，建议 N=3）
2. 所有行**科目置信度 = high**
3. **CRA 凭证等级达标**（按金额档位该有的字段齐全）
4. 金额 **≤ 客户设定阈值**（默认 $200）
5. **不是**疑似重复
6. 税码由规则表命中，**非 AI 推断**

任一不满足 → 进人工复核队列。自动过账的单据仍进「已自动过账」列表供抽查，且审计留痕。

> 这是相对 Dext 的差异点：Dext 的 auto-publish 只看供应商，我们把**凭证合规**和**置信度**也做成门禁。

### 2.5 已付 / 未付的分叉（当前代码的缺口）

现在代码只会建 Bill。正确规则：

| 单据形态 | QBO 对象 | 判定依据 |
|---|---|---|
| 收据（已付，刷卡/现金） | **Purchase / Expense**，直接冲对应银行或信用卡账户 | OCR 有付款方式、或票据类型为 receipt、或已匹配到银行流水 |
| 供应商发票（未付，有账期） | **Bill**（挂 AP），付款后再记 Bill Payment | 有 due date / payment terms、未匹配到银行流水 |
| 信用卡退款 / 贷记单 | Credit Note / Refund | 金额为负 |

**这是必须补的业务规则**，否则应付账款会虚增。

## 三、与现有代码的差距

| 已有 | 差距 |
|------|------|
| 五段状态机、规则优先分类、置信度 rollup、学习飞轮 | 缺**税码规则表**（`taxCode` 字段有、逻辑无） |
| 银行对账 + 缺收据清单 | 缺「追票工单」闭环（提醒客户目前只是前端状态） |
| 复核队列按置信度排序 | 缺**CRA 凭证等级**字段与排序权重 |
| 确认即可录入的状态机 | **P5 QBO 全部未写**；且缺已付/未付 → Expense/Bill 的分叉 |
| 供应商规则学习 | 缺规则**命中次数**统计（绿色通道门槛 1 要用） |
| — | 缺客户级配置：自动过账阈值、省份、默认税码 |

| # | 议题 | 定论 | 已写入契约 |
